# Keys Radar 研发验收标准

## S0 Symphony 研发环境

| 事项 | 通过标准 |
| --- | --- |
| 环境与版本 | 检查 macOS、架构、Git、gh、Python、uv、Codex 和已有 Symphony，记录真实结果及保留的既有工程 |
| 配置 | 标注参考的官方稳定版，检查 front matter、钩子、Codex schema、GitHub 状态映射与并发数 |
| 门禁 | 本地测试能复现错误 Issue、非运行状态、缺审批、缺依赖、无前置基线、重复执行、阶段越权等拦截 |
| 安全交付 | 隔离分支，保存改动、未跟踪文件和日志。操作员独立审核并记录结果，授权和凭证保留在主机 |
| 本机集成 | 已验证兼容 Symphony 二进制实际载入配置，Codex stdio initialize 成功 |
| 平台集成 | 用户确认授权后，在约定 GitHub Issues 仓库验证读取、标签过滤、暂停、回收留档和人工审核；平台未授权时记录为待联调 |
| 范围 | 仅 S0，保留现有 P0 业务实现。关闭前台验证进程，交付报告及下一步所需权限 |

S0 的本地交付和真实运行验收可分别记录。当真实运行验收未完成时，S0 仍待人工验收，P0-01 保持待授权。

## P0 基础工程及人工需求管理

- P0-01 至 P0-05 均有独立交付报告、可追溯测试证据及人工验收记录。
- 锁文件安装成功，数据库初始化、迁移往返、完整性、外键和去重约束通过。
- 三种人工录入、字段校验、证据关系、部分批次处理、并发去重、事务回滚和重试通过。
- 7 个接口的状态、分页、筛选和统计通过。模拟数据与实际业务分组正确，测试数据均显式模拟并隔离。
- 回环 TCP 短时启动并实测健康、就绪、业务 API 和 OpenAPI。TCP 环境限制作为未通过项记录。
- P0 阶段通过由项目负责人书面确认。P1 的范围和权限单独授权。

P1–P9 使用 [路线图](ROADMAP.md) 的阶段标准。商业机会验收同时执行 [市场分析](COMPETITIVE_ANALYSIS.md)、[评分规则](SCORING_RULES.md) 和 [报告规范](OPPORTUNITY_REPORT_SCHEMA.md)。
