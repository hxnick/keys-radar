# 开发路线

| 阶段 | 建设内容 | 独立验收 |
| --- | --- | --- |
| P0 | 本地工程、配置、迁移、需求人工导入及证据查询 | 空库迁移、三种导入、去重、分页筛选及真实与模拟分组统计 |
| P1 | V2EX 官方接口及合规数据源 | 访问规则已确认，重复拉取可去重，来源和采集任务可追溯 |
| P2 | 模型 Provider、有效需求识别、广告过滤、场景及付费信号 | 结构化结果、证据评级、预算约束和模型版本记录 |
| P3 | 聚类、独立证据计数和趋势 | 样本复核能够识别转载、重复和独立证据 |
| P4 | 解决方案、竞品、价格、功能及用户评价 | 国内外、商业、免费、开源和人工替代调查有覆盖记录 |
| P5 | 市场缺口、差异化定位及优势验证任务 | 关联原始需求、竞品能力与可执行的验证方法 |
| P6 | GitHub 技术匹配、成熟度及许可初筛 | 功能复用与开发缺项明确，授权及运行状态可追溯 |
| P7 | 商业评分、定价、成本、获客及报告 | 假设、计算与真实证据可区分，待验证事项可追踪 |
| P8 | 管理前端和人工操作流程 | 工作台、各业务库、审核及设置可操作 |
| P9 | 定时任务、飞书摘要、人工立项及付费反馈 | 定时执行可追踪，立项有人工审核记录，付费验证可回写 |

每阶段验收后由项目负责人确认下一阶段。P1 前置条件包括 P0 验收、核实 V2EX 接口授权和限流规则、确认采集字段与保留范围。


## S0 后的 P0 任务依赖

S0 由项目负责人单独验收。通过并明确授权后，依次执行 [P0-01](../tasks/P0-01.md) → [P0-02](../tasks/P0-02.md) → [P0-03](../tasks/P0-03.md) → [P0-04](../tasks/P0-04.md) → [P0-05](../tasks/P0-05.md)。每个任务先复核既有实现，再处理经授权的缺口。调度器需读取人工验收记录，并校验已验收的 Git 基线包含于当前 HEAD。
